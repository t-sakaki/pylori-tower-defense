# 3D移行提案: ピロリ菌タワーディフェンス

現行の`packages/web`はPhaser 3(2D Canvas)ベースで実装されている。本ディレクトリは、
ゲームを没入感のある3D表現へ進化させるための提案一式(アセット生成スクリプト・
ライティング/カメラ構成・座標変換ロジックのサンプル)をまとめたものであり、
既存の2Dゲームロジック・実装には一切変更を加えていない。

## 内容物

- [`blender_asset_generator.py`](./blender_asset_generator.py)
  BlenderのText Editorに貼り付けて実行すると、以下を自動生成するスクリプト。
  - `Stage_Tunnel`: 粘膜状にうねるトンネルコース(頂点の波状変形 + Displaceモディファイアによる表面ノイズ + Solidify)
  - `HPylori_Enemy`: UV球をSimpleDeform(Twist)で桿菌シルエットに変形し、螺旋カーブの鞭毛を複数束ねたクリーチャー
  - `Tower_Antibiotic`: 八角柱の台座 + Boolean Unionで作ったカプセル本体 + 放射状の砲身、ネオンEmissionマテリアルによるサイバーパンク風タワー
  - 胃内部を想起させる暗色World設定 + ネオンカラーのポイントライト4灯
  - 戦略的な俯瞰(クォータービュー)カメラ

- [`threejs_migration_sample.js`](./threejs_migration_sample.js)
  2Dのゲームロジック(移動パス・攻撃範囲判定)を3D空間の座標系に変換する実装例(Three.js)。
  - 2Dウェイポイント配列 → `CatmullRomCurve3` によるスプライン経路への変換
  - 経路パラメータ`t`による敵の移動(2D時代の「進行度」ロジックをそのまま流用可能)
  - タワーの攻撃範囲判定をXZ平面上の距離判定に単純化し、2Dの円判定の数式をほぼそのまま流用
  - HP/ダメージ等のステータス管理ロジックは完全に据え置き

## 3D移行ロードマップ

1. 既存の2Dゲームロジック(移動・攻撃・HP・ウェーブ制御など)をエンジン非依存のコアロジックとして分離する
2. 3D座標変換レイヤー(スプライン評価・進行方向の回転計算・XZ平面距離判定)を追加する
3. Blenderで生成したアセットをglTF(.glb)でエクスポートし、採用するレンダリング方式(Three.js / Phaser 3Dプラグイン / 別エンジンへの移行)にインポートする
4. カメラ・ライティングは本スクリプトのWorld/Light設定を参考値として実装環境側に再現する

## 注意事項

- 本提案は概念実証・叩き台であり、現行のPhaser実装への組み込みは別途設計判断が必要(Phaser自体は2D特化のため、3D化には別レンダラーとの併用または移行が前提となる)。
- `threejs_migration_sample.js`はスタンドアロンのサンプルコードであり、`packages/web`のビルドには含まれていない。
